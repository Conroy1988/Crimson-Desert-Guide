There is no defensible universal **best weapon** without specifying character, acquired skills, enemy, arena, player control method and patch version.

The correct question is:

> Which weapon and skill package lets this player solve this encounter consistently?

## Compare weapon families by function

Use the following criteria instead of attack power alone.

| Criterion | What to test | Why it matters |
|---|---|---|
| Reach | Maximum reliable hit distance and vertical coverage | Determines how safely you can punish and control space |
| Start-up | How quickly a useful attack becomes active | Affects interruption and short openings |
| Recovery | How long before movement or defence returns | Determines how punishable your offence is |
| Resource cost | Stamina or Spirit used by core actions | Controls how often the weapon can attack safely |
| Crowd control | Stagger, knockback, launch, area coverage | Determines group-fight stability |
| Mobility | Slides, lunges, aerial movement, evasive attacks | Changes entry, escape and camera management |
| Defensive fit | Block, counter, evasive follow-up and safe disengage options | Determines error tolerance |
| Ranged access | Native ranged attacks or compatible secondary options | Helps control flying, distant or dangerous targets |
| Terrain tolerance | Performance on slopes, narrow spaces and elevation changes | Prevents a strong moveset failing in real arenas |
| Skill dependence | How much of the weapon's value requires later skills | Affects early availability and investment |

A weapon that wins a stationary damage test can still be a poor practical choice if its recovery, resource cost or camera demands make it unreliable.

## Establish a core package

A dependable loadout needs answers to five problems.

1. **Safe opener** — an attack that can test range without committing the entire resource bar.
2. **Reliable punish** — a short sequence for confirmed enemy recovery.
3. **Group control** — an action that creates space, stagger or area denial.
4. **Defensive exit** — a block, counter, dodge follow-up or movement option.
5. **Range answer** — a ranged weapon, projectile, gap closer or terrain solution.

Do not build around ten situational skills before these five functions work.

## Use the Skills menu deliberately

Official updates improved the Skills interface in several stages:

- Patch 1.00.02 separated skill names and descriptions by weapon type and improved **Watch and Learn**.
- Patch 1.08.00 added a weapon filter under **Skills → Search**.
- Later patches continued correcting equipment-specific skill behaviour, resource consumption and Quick Swap interactions.

### Search by the current problem

When the loadout fails, search for a skill that solves the failure:

| Failure | Useful skill property |
|---|---|
| Enemy outranges you | gap closer, projectile or extended reach |
| Long recovery is punished | shorter finisher, cancel route or defensive follow-up |
| Surrounded | area attack, knockback, launch or movement |
| Stamina collapses | lower-cost core action or Spirit-based alternative |
| Flying target | ranged or aerial access |
| Block pressure | counter, repositioning or resource-efficient defence |
| Target escapes punish | tracking, lunge or faster start-up |

A visually impressive skill that does not solve a current failure is optional, not foundational.

## Watch and Learn

**Watch and Learn** is a skill-learning feature whose usability was improved in Patch 1.00.02.

Use it as an acquisition route, but verify the learned action in a controlled encounter before integrating it into a serious loadout.

After acquiring a skill:

1. read its weapon and state requirements;
2. identify its resource cost;
3. practise the raw input without enemies;
4. test whether it tracks or changes facing;
5. test its recovery after hit, block and miss;
6. check whether it changes behaviour in the air, on slopes or near walls;
7. decide which existing function it replaces.

Adding a skill without removing redundancy often makes the control scheme harder without improving the build.

## Quick Swap is stateful

Patch 1.08.00 clarified that **Quick Swap** switches to equipment in the slot that was previously drawn. This is not the same as selecting a permanent preferred weapon.

Before relying on Quick Swap:

- confirm which item is currently drawn;
- confirm the previous drawn slot;
- practise the swap after movement, defence and another skill;
- check the resource requirement for any skill-linked swap action;
- avoid assuming the same result after tools or secondary weapons have been used.

Patch history includes fixes for Quick Swap consuming the wrong resource with particular equipment. If a reproducible mismatch remains, record the weapon, character, resource state and input sequence and check current patch notes.

## Build for the character, not only the weapon name

Characters can have different skill access, unarmed options, counters and equipment compatibility.

Examples from official patches include:

- Oongka receiving new unarmed skills in Patch 1.06.00;
- Damiane receiving additional unarmed combat support in a later update;
- character- and weapon-specific fixes for counters, aerial actions, charged shots and grapples;
- equipped-gear lock persistence for Oongka and Damiane being fixed in Patch 1.15.00.

Do not assume a weapon family behaves identically across characters simply because the item category is shared.

## The six-test weapon trial

Use an ordinary repeatable encounter and keep gear refinement unchanged.

### Test 1 — neutral reach

- Stand outside enemy range.
- Find the farthest distance where the basic opener hits reliably.
- Repeat on flat ground and a slope.

### Test 2 — safe recovery

- Use the shortest intended punish.
- Immediately attempt movement or defence.
- Record whether the enemy can retaliate before control returns.

### Test 3 — resource cycle

- Perform the normal opener, punish and defensive exit.
- Count how many cycles are possible before stamina or Spirit becomes unsafe.
- Do not include unrealistic uninterrupted attacks.

### Test 4 — group stability

- Fight three or more ordinary enemies.
- Measure success by camera control and damage avoided, not kill speed alone.
- Note which action prevents encirclement.

### Test 5 — target mismatch

- Test against a fast target, large target and ranged or elevated target.
- Record where the weapon needs secondary equipment or a specific skill.

### Test 6 — miss and block behaviour

- Deliberately miss the core attack.
- Let the enemy block or armour through it.
- Record how exposed the recovery becomes.

A weapon passes when its weaknesses are understood and covered—not when every test is perfect.

## What to unlock first

Prefer skills that improve repeatability:

1. a defensive or evasive answer you currently lack;
2. a safe punish for short openings;
3. a group-control tool;
4. a reliable range answer;
5. mobility that improves positioning;
6. damage extensions after the core loop already works.

Damage-only upgrades are more valuable when the player can consistently reach the relevant opening.

## When to change weapon family

Change weapon family when:

- the current weapon cannot solve a recurring target type even with available skills;
- its defensive model conflicts with the player's control strengths;
- its resource cycle repeatedly leaves no escape reserve;
- the arena or camera consistently defeats its reach and recovery profile;
- another weapon provides the same function with fewer execution demands.

Do not change solely because one attempt went badly or another weapon has a larger displayed number.

## When to keep practising

Keep the current weapon when:

- failures are caused by unrecognised enemy cues;
- you are extending attacks beyond confirmed openings;
- lock-on or camera control is failing;
- the current core package has not been practised independently;
- the weapon is under-refined relative to content you have already reached;
- a known issue is disrupting the intended skill or input.

Use [Combat Fundamentals](/systems/combat/) to correct execution and [Boss & Encounter Diagnosis](/systems/boss-diagnosis/) to identify the actual failure before spending materials.
